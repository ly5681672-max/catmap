# `lyq_alkene_epoxidation` 代码逐行解读

> 面向当前 `main` 分支生成。本文只解读**代码/模型文件**：两个 Python 脚本、一个 CatMAP `.mkm` 配置和 `test.ipynb` 中实际代码单元。`*_energies.txt`、`*.csv`、`energies.txt` 属于数据文件；`.ipynb_checkpoints` 是 Jupyter 自动备份，不重复逐行解读。

## 1. 整体数据流

```text
DFT/自由能原始数据
    ↓
data_only_not_executable.py / generate_input1.py
    ↓ 计算形成能：E_form = E_system - E_slab(表面态) - Σ n_i E_ref,i
tini_energies.txt / tini_energies.csv
    ↓ 汇总为多表面 energies.txt
alkene_epoxidation.mkm
    ↓ CatMAP ReactionModel
稳态覆盖度、反应速率、生产速率、控制系数
    ↓
test.ipynb
    ↓
PDF 图和 *_table.txt
```

### 当前代码中最值得注意的三点

1. 两个第一阶段 Python 脚本都把非气相 `surface_name` **硬编码成 `tini`**。因此它们当前本质上是“单个 TiNi 表面输入生成器”；若要批量生成 TiFe/TiMn/...，应把表面名参数化。
2. `.mkm` 已经改成以 `OOH_s`、`O_s` 为二维描述符，但 `test.ipynb` 第一单元仍有 `H reactivity`、`C2H5 reactivity`、`C2H5_s` 等旧示例标签，和当前反应网络不一致。
3. `test.ipynb` 中 `import page`、变量名 `MgO` 也明显带有旧项目痕迹；它们不是当前烯烃环氧化模型的必要组成。

## 2. `1-generating_input_file/data_only_not_executable.py`

### 文件作用

- 生成 `tini_energies.txt`；
- 创建最小 `ReactionModel`；
- 用 `TableParser` 检查生成文件是否能被 CatMAP 正确识别。

```text
E_form = E_gas - Σ n_i E_ref,i

表面态 / 过渡态：
E_form = E_system - E_slab - Σ n_i E_ref,i
```

因此 `ref_dict` 的物理定义必须在整个数据集中保持一致，否则不同表面之间的形成能不可直接比较。

### `species_definitions`

这是 CatMAP 模型层的物种元数据。它不保存所有能量，而是补充：
- 储库活度/pressure；
- 位点映射；
- 特殊名称的元素组成；
- 其他模型属性。

能量主体仍来自 `energies.txt`。

## 7. 反应网络逐步解释

当前 `.mkm` 中 8 个步骤可理解为：

1. `H2O2` 吸附到空位点。
2. 吸附的 `H2O2` 被活化，形成 `Ha* + OOH*`。
3. 1-己烯吸附。
4. `OOH*` 与吸附己烯通过 `OOH-C6H12*` 过渡态发生环氧化，生成环氧产物吸附态、表面 O 和 `Hb*`。
5. 环氧产物脱附进入储库。
6. `Hb*` 向表面 O 转移 H，经 `Hb-O*` 过渡态生成 `OH*`。
7. `Ha* + OH*` 生成吸附水并释放空位点。
8. 水脱附，完成位点再生。

从机理结构看，`OOH_s` 描述 H2O2 活化/环氧化前体稳定性，`O_s` 描述环氧化后残余表面氧的稳定性，因此把二者选作二维描述符具有明确的机理含义。
